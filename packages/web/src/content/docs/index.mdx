```bash
sweny workflow create "scan our repo for security issues, check dependencies \
  for vulnerabilities, and create Linear tickets for anything critical"
```

One sentence in, a workflow YAML out. You review it before it runs.

Don't like the result? Edit it the same way you created it:

```bash
sweny workflow edit security_audit.yml "add a quality gate that rejects \
  vague findings, and loop back to re-scan if rejected"
```

## Built-in workflows

SWEny ships two built-in workflows you can run immediately:

<CardGrid>
  <Card title="Triage" icon="warning">
    Monitors your observability platform for errors, investigates root causes, creates issues, writes fixes, and opens
    PRs, automatically. [Learn more](/workflows/triage/)
  </Card>
  <Card title="Implement" icon="rocket">
    Takes an existing issue, analyzes the codebase, writes a fix, opens a PR, and notifies your team. Trigger it
    manually or chain it from Triage. [Learn more](/workflows/implement/)
  </Card>
</CardGrid>

```bash
sweny triage --dry-run          # investigate production errors
sweny implement ENG-123         # fix a tracked issue and open a PR
```

Or [build your own](/workflows/custom/) from a single sentence with `sweny workflow create`.

## E2E browser testing

Generate AI-driven end-to-end tests for any web app, no test scripts to write:

```bash
sweny new e2e        # wizard asks about your flows → generates workflow YAML
sweny workflow run   # AI agent drives a real browser to test your app
```

The wizard supports 7 flow types: registration, login, purchase, onboarding, upgrade, cancellation, and custom. Each generates a self-contained workflow with auto-generated test credentials and optional cleanup. [Get started with E2E testing](/cli/e2e/)

## Run it on a schedule

Deploy any workflow to GitHub Actions with three secrets and a cron schedule. SWEny monitors your production errors and opens fix PRs while you sleep.

```yaml
# .github/workflows/sweny-triage.yml
- uses: swenyai/triage@v1
  with:
    claude-oauth-token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
    observability-provider: sentry
    sentry-auth-token: ${{ secrets.SENTRY_AUTH_TOKEN }}
```

[Full Action guide](/action/): setup, scheduling, and service maps.

## Use it from Claude Code

Install the [Claude Code plugin](/advanced/mcp-plugin/) and get slash commands, MCP tools, and a startup hook, without leaving your conversation:

```
/plugin marketplace add swenyai/sweny
/plugin install sweny@sweny-official
```

Then type `/sweny:triage`, `/sweny:implement ENG-123`, `/sweny:e2e-run`, or any of the 9 available commands. Claude can also autonomously delegate tasks to SWEny's DAG executor via MCP tools.

## Connect to your stack

SWEny connects to the tools you already use (GitHub, Linear, Sentry, Datadog, BetterStack, Slack, and more) through built-in [skills](/skills/) and [MCP servers](/advanced/mcp-servers/). Set an API key and the skill is ready. Bring your own MCP servers to connect anything else.

## Studio

[Studio](/studio/) is a visual DAG editor. Run it from a repo checkout with `npm run dev -w @sweny-ai/studio`. Live mode connects to a WebSocket or SSE event URL you provide and overlays node state as events arrive.
