## Your first run

SWEny runs nodes on Claude Code by default; Codex is shipped and pi and ACP agents are experimental (see [Agents and policies](/getting-started/agents-and-policies/)). Before you start, credentials by agent: Claude Code needs a `CLAUDE_CODE_OAUTH_TOKEN`, an `ANTHROPIC_API_KEY`, or a Claude Code login; Codex needs `CODEX_API_KEY` or `OPENAI_API_KEY`, or a `codex login`; pi needs the API key of the model provider it calls; ACP agents authenticate on their own (pass their key var through `SWENY_ENV_PASSTHROUGH`).

```bash
npx @sweny-ai/core new      # pick a named workflow; explain-repo needs no skill credentials
npx @sweny-ai/core check    # preflight: is your agent logged in?
npx @sweny-ai/core workflow run .sweny/workflows/explain-repo.yml
```

Install once with `npm install -g @sweny-ai/core` and the binary is `sweny`. The run ends with an answer and a receipt: nodes, tool calls, duration, tokens, cost, and the policy the agent ran under. Then `sweny runs` lists your history and `sweny runs diff` shows what changed between two runs.

Want to watch it first? `sweny try` replays a recorded demo with no login and no network. It is sample data, not a real run.

## Built-in workflows

SWEny ships two built-in workflows you can run immediately:

  <Card title="Triage" icon="warning">

```bash
sweny triage --dry-run          # investigate production errors
sweny implement ENG-123         # fix a tracked issue and open a PR
```

Or [build your own](/workflows/custom/) from a single sentence with `sweny new` ("Describe your own").

## E2E browser testing

Generate AI-driven end-to-end tests for any web app, no test scripts to write:

```bash
sweny new e2e        # wizard asks about your flows → generates workflow YAML
sweny workflow run   # AI agent drives a real browser to test your app
```

The wizard supports 7 flow types: registration, login, purchase, onboarding, upgrade, cancellation, and custom. Each generates a self-contained workflow with auto-generated test credentials and optional cleanup. [Get started with E2E testing](/cli/e2e/)

## Run it on a schedule

Recurring packs (`weekly-digest`, `dependency-drift`, `pr-risk-review`) are read-only workflows with a GitHub Actions trigger. `sweny new --template weekly-digest` writes both files. Run it once locally first, then commit them.

```yaml
# .github/workflows/sweny-weekly-digest.yml (written by sweny new)
- uses: swenyai/sweny@v5
  with:
    workflow: .sweny/workflows/weekly-digest.yml
    claude-oauth-token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
```

[Packs](/workflows/packs/) and the [Action guide](/action/): setup, scheduling, and service maps.

## Use it from Claude Code

Install the [Claude Code plugin](/advanced/mcp-plugin/) and get slash commands, MCP tools, and a startup hook, without leaving your conversation:

```
/plugin marketplace add swenyai/sweny
/plugin install sweny@sweny-official
```

Then type `/sweny:triage`, `/sweny:implement ENG-123`, `/sweny:e2e-run`, or any of the 9 available commands. Claude can also autonomously delegate tasks to SWEny's DAG executor via MCP tools.

## Connect to your stack

SWEny connects to the tools you already use (GitHub, Linear, Sentry, Datadog, BetterStack, Slack, and more) through built-in [skills](/skills/) and [MCP servers](/advanced/mcp-servers/). Set an API key and the skill is ready. Bring your own MCP servers to connect anything else.

## Studio

[Studio](/studio/) is a visual DAG editor. Run it from a repo checkout with `npm run dev -w @sweny-ai/studio`. Live mode connects to a WebSocket or SSE event URL you provide and overlays node state as events arrive.
